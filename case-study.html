IIMUN 2025 - Website Case Study

Designing and building a conference website for a student-run Model United Nations event.

January 2025 ~2 weeks HTML / CSS / JS Solo project

Goal

The Indus International Model United Nations conference needed a website. Their old one was a basic Google Site that looked outdated, wasn't mobile-friendly, and didn't reflect the quality of the event. The secretariat wanted something professional enough to show parents and school administrators, easy to update, and fast - no bulky frameworks or expensive hosting.

The primary goals were:

  • Present conference information clearly to prospective delegates and their parents
  • Handle online registrations with client-side validation
  • Look premium enough to be shared on LinkedIn and school communications
  • Work perfectly on mobile (most of their traffic comes from phones)
  • Be maintainable by students who might not know web development

Design Process

I started by looking at other MUN conference websites - both Indian and international. Most fell into two categories: overly complex sites built with page builders that loaded slowly, or minimal single-pagers that lacked information. The best ones had a clear hierarchy, used gold/navy colour schemes (standard for MUN), and put the registration call-to-action front and centre.

Colour & Typography

I chose a deep navy and gold palette - it's the unofficial colour scheme of MUN branding and immediately signals "diplomatic conference." For light mode, I inverted to white backgrounds while keeping gold accents. Playfair Display for headings gives a formal, establishment feel; Inter for body text keeps it readable at small sizes on mobile.

Layout Decisions

The hero section needed to do three things simultaneously: show the conference name and date, display a countdown (urgency), and provide a registration button. Below that, the flow is About > Committees > Team > Schedule > Register > FAQ > Contact - a logical progression that answers questions in the order a prospective delegate asks them.

The committees section was the hardest to design. Each committee is a card with name, agenda, difficulty, and size. I experimented with a table layout, an accordion, and finally settled on a responsive card grid because it works equally well for 3 committees or 10.

Problem

7 committees with different difficulty levels, sizes, and types. Needs to be scannable.

Solution

Card grid with colour-coded difficulty badges (green=beginner, blue=intermediate, orange/crisis=advanced).

Problem

Dark/light mode would double the CSS work.

Solution

CSS custom properties. 95% of styles are shared; only colour values change between themes.

Problem

The schedule spans 3 days - showing all at once is overwhelming.

Solution

Tabbed interface. Each day is a separate view. The active tab uses the gold gradient.

Tech Stack & Why

HTML5 CSS3 Vanilla JS Font Awesome 6 Google Fonts GitHub Pages

No frameworks - zero dependencies. The entire site is three files (plus the case study page). This was deliberate: the site needs to load fast on school Wi-Fi and mobile data. No React build step, no npm install, no CMS to maintain. If a future secretariat member wants to change committee details, they can edit the JS array directly without understanding a framework.

Key Implementation Details

  • Theme toggle: Saves preference to localStorage. Respects system preference on first visit. Transitions smoothly via CSS custom properties.
  • Countdown timer: Pure JS date math. Set to IST (GMT+5:30) for the February 21 start date. Updates every second.
  • Scroll animations: IntersectionObserver - no scroll event listeners, so performance is good even on low-end devices.
  • Form validation: Real-time error messages with red borders on invalid fields. Success state replaces the form after submission (no actual POST - this is a static site).
  • SEO: Meta tags, semantic HTML, descriptive alt text on the hero image.
  • Accessibility: Focus-visible outlines, aria-labels on icon buttons, proper heading hierarchy, reduced-motion media query.

Problems Solved

1. Making a static site feel interactive

A static HTML site risks feeling flat. I added micro-interactions - card hover effects with a light sweep, smooth tab transitions, the countdown ticking, scroll-triggered fade-ins - that give the impression of a more complex application without any backend.

2. Balancing content density

MUN websites carry a lot of information: 7 committees, 8 team members, 3-day schedule, 10 FAQs. The challenge was fitting everything on one page without it feeling like a wall of text. The solution was progressive disclosure - tabs for schedule days, accordion for FAQs, and cards for committees only show preview content until hover.

3. Dark/light mode without maintenance burden

This was a CSS architecture problem. Using custom properties for every colour value let me define two themes in ~30 lines each. Every component automatically works in both modes. The alternative - writing separate dark mode overrides for each class - would have been 4x the CSS and fragile.

4. Mobile-first without a framework

I wrote the desktop layout first, then added breakpoints at 1024px, 768px, and 480px. The key mobile decisions: stack multi-column layouts vertically, make the nav a slide-down drawer, and ensure tap targets are at least 44px (Apple's guideline).

Final Result

The site serves its purpose: delegates and parents can find all conference information in one place, register online, and get a professional impression of the event. It scores 95+ on Lighthouse performance, works offline-ready (the static assets cache well), and takes about 1.2 seconds to load on 3G.

The secretariat's favourite feature is the dark mode toggle - it became a talking point during school assemblies. For me, the best outcome is that the team now has a template they can reuse for future editions by just updating the JS data arrays.
